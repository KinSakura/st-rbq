# 发版流程（每次更新都照这个来）

> ⚠️ **最重要的一条**：`manifest.json` 里的 `version` 字段 ——
> 插件内置的「更新检查」就是拿**远端仓库里的 `manifest.json` 的 version** 和本地比。
> **不 bump 它，用户就永远收不到更新提示。**

---

## 一、四件套要同步（缺一个就会出问题）

| # | 改什么 | 在哪 | 不同步的后果 |
|---|---|---|---|
| ① | **版本号 `version`** | `manifest.json` | 用户收不到更新提示 ✗ |
| ② | **入口文件名** | `manifest.json` 的 `js` → `boot-vNNNN.js`（新建一个） | 浏览器拿旧缓存 ✗ |
| ③ | **`?v=NNNN`** | `index.js` / `ui/panel.js` / `ui/views/*.js` 里的 import | 同上，混着旧文件跑 ✗ |
| ④ | **角标版本** | `ui/panel.js` 里的 `vX.Y.Z` | 你没发判断用户到底加载了哪版 ✗ |

举例：从 `2.9.3` 发到 `2.9.4`

```
manifest.json     "version": "2.9.4"
                  "js": ["boot-v2940.js"]
boot-v2940.js     新建，内容一行：import './index.js?v=2940';
index.js          所有 ?v=2930 → ?v=2940
ui/panel.js       角标 v2.9.3 → v2.9.4；views/*.js?v=2930 → ?v=2940
ui/views/*.js     文件头注释里的版本号（有就顺手改）
```

> 版本号规则：`v2.9.3` → `?v=2930`（把点去掉补齐四位，只是给浏览器区分缓存用的 ✓）

## 二、发版前的自检（必做）

```bash
# 1) 在扩展目录里跑核心冒烟测试（纯 Node，不需要酒馆）
node tools/smoke-test.mjs --quiet        # 期望：通过 41 项，失败 0 项

# 2) 扫一遍有没有写死的本地路径（别人 clone 下来会跑不起来）
#    PowerShell：
Get-ChildItem -Recurse -File -Include *.js,*.mjs | Select-String -Pattern 'D:\\|C:\\Users|_st-test|localhost:8788'
#    期望：没有输出

# 3) 确认入口文件存在
Test-Path boot-v2940.js
```

装到酒馆里再验一次（能看到界面）：

```
1. 扩展放进 SillyTavern/data/default-user/extensions/
2. 硬刷新（Ctrl+Shift+R）
3. 看面板右上角角标 = 新版本号 → 就是加载成功了
4. 随便发一条消息，确认侧路跑得起来
```

## 三、上传到 GitHub

### 改了哪些就传哪些（网页版）

```
https://github.com/KinSakura/st-rbq/upload
```

⚠️ 网页上传**不能选目标文件夹** ✗ → `tools/` 里的文件要先进 `tools/` 目录再 `Add file → Upload files` ✓

### 或者用 Git（推荐，以后省事）

```bash
cd <你的 st-rbq 目录>
git add .
git commit -m "v2.9.4：修了什么"
git push
```

## 四、发一个 Release（别人可以"下载即用"）

```
仓库 → Releases → Draft a new release
  Tag：v2.9.4（Choose a tag → Create new tag）
  Title：RBQ 数据库 v2.9.4
  Describe：写这次改了什么（用户会在更新提示里看到版本号，值得来 Release 页看细项）
  附件：把打包的 zip 拖进去
→ Publish release
```

打包命令（在 `st-rbq` **的上一层**执行）：

```powershell
Compress-Archive -Path .\st-rbq\* -DestinationPath .\st-rbq-v2.9.4.zip -Force
```

## 五、用户那边会发生什么

```
用户打开酒馆 → 6 秒后插件自动查一次（多源兜底：jsDelivr → raw → GitHub API）
  · 远端 version 比本地新 → 顶部出现横幅「⬆ 插件 2.9.4」+ 弹一次通知
    点横幅 → 调酒馆的扩展更新接口（本地是 git clone 的话能直接更新 ✓）
    不是 git 目录 → 提示手动下载地址 ✓
  · 同一个版本只提示一次（记在配置的 notifiedVersion 里 ✓）
  · 点「忽略此版本」→ 不再显示横幅（记在 dismissVersion ✓）
  · 查不到（网络不通）→ 静默失败，不影响使用 ✓（日志里有一行说明 ✓）
```

设置页「插件更新」卡片里能看到：**当前版本 / 远端版本 / 什么时候查的 / 本次用的哪个源** ✓

## 六、常见问题

**Q：用户说没收到更新提示？**
1. 确认你**推上去了**，并且仓库里的 `manifest.json` 的 `version` **真的变了**
2. 确认仓库是 public（private 仓库 raw/jsDelivr 拉不到 ✗）
3. 让用户 F12 搜 `版本检查` 看那行日志（会写明当前/远端/错误原因）

**Q：jsDelivr 有缓存，会不会读到旧的？**
jsDelivr 对 `@main` 有缓存（一般几分钟到几小时）✗ → 急着让别人看到就让他先点一次「检查更新」（那是 no-store ✓），
或把源改成 `raw.githubusercontent.com`（无缓存但国内可能不通 ✓）。

**Q：改了表结构 / 别名 / 预设怎么办？**
- 表结构、别名：跑 `node tools/build-schema.mjs …` 与 `node tools/build-aliases.mjs` 重新生成 `data/` 里的四份文件（`.js` 和 `.json` 都要 ✓ 运行时读的是 `.js` ✗ 只改 json 等于没改 ✓）
- 内置预设：改 `presets/index.json` 的 `version` → 用户那边会出现「⬆ 预设 x.y」横幅，点一下就能导入 ✓
