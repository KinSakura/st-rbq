## 这是什么

**RBQ 数据库**是一个 SillyTavern 第三方扩展。它做三件事：

| | 说明 |
|---|---|
| **① 给 AI 一个数据库** | 角色 / 关系 / 地点 / 物品 / 技能 / 任务 / 势力 / 纪事……用表格存，**压缩上下文**，让 AI 记住更多 |
| **② 让另一个 AI 记账** | 正文照常由主 AI 写；**填表交给「侧路 API」**——正文写完后，扩展再发一次请求，让便宜的模型去填表 |
| **③ 给人一堆视图** | 表格是给 AI 的存储格式，**给人看的是视图**：仪表盘 / 角色卡 / 关系图 / 地图 / 任务看板 / 装备纸娃娃…… |

一句话：**剧情归剧情，数据归数据，各用各的模型。**

---

## 核心思路（为什么这么设计）

```
主 AI（贵 / 好）                侧路 AI（便宜 / 快）
   │                              │
   ├─ 写正文 ────────────────────┤
   │                              └─ 读正文 → 只输出表格写入指令 → 扩展入库
   │
   └─ 收到注入的「当前数据库」+「相关记忆」→ 继续写下一轮
```

- **主 AI 不写数据**：正文里不需要 `data` 标签，也不该出现表格内容。
- **表格数据会发给主 AI**：它就是这么"记住更多"的；但**回滚之后发的永远是回滚后的状态**。
- **数据为空时不发假数据**：会明确告诉主 AI「数据库为空，按角色卡 / 世界书 / 预设自由发挥」。

## 功能一览

- ✅ **侧路 API 填表**：并发 3 / 重试 3 / 超时 120 秒（都可调），失败时卡片会显示「超时重试 1/3」
- ✅ **长期记忆**：按角色归档 + 相关度召回，注入到主 AI 的上下文
- ✅ **逐楼快照 + 精确回滚**：点重新生成 / 删楼层，表格**当场**回到对应状态
- ✅ **16 个标签页**：视图 / 侧路 API / 数据 / 结构 / 审计 / 记忆与召回 / 轮次与总结 / 附加功能 / 抢话与时间框 / 四选一 / 大纲 / 灵感 / 离场与实体 / 正则工坊 / 设置 / 变量管理
- ✅ **沉浸式视图**：仪表盘 + 角色坞（一圈三段 HP/MP/SP）+ 角色卡 + 关系图 + 地图 + 看板……
- ✅ **头像**：点角色卡头像上传，视图坞 / 关系图同步显示
- ✅ **角色设定自动处理**：把 `{{user}}` 设定用标签包起来并移到「聊天内 · 深度 0」
- ✅ **预设位置标记**：预设里名字带 `🔒↓` / `🔒↑` 的提示词，自动拼到侧路提示词的上面 / 下面
- ✅ **正则工坊**：向导式生成酒馆正则，一键装进全局正则（装完自动刷新）
- ✅ **零构建**：纯 ESM，改完直接刷新浏览器即可
- ✅ **内置更新提示**：自动检查 GitHub 仓库的新版本 → 顶部横幅 + 一键更新（多源兜底，国内一般能通）

## 安装

### 方式 A：手动拷贝（推荐）

1. 下载本仓库（`Code → Download ZIP`）或 `git clone`
2. 把整个 **`st-rbq` 文件夹**放进酒馆的扩展目录：

```
SillyTavern/
└─ data/
   └─ default-user/
      └─ extensions/
         └─ st-rbq/            ← 整个文件夹放这里（里面有 manifest.json）
            ├─ manifest.json
            ├─ boot-v2930.js
            ├─ index.js
            ├─ core/  ui/  data/  prompts/  presets/  tools/
            └─ ...
```

3. **硬刷新**酒馆页面（`Ctrl + Shift + R`）
4. 出现 `RBQ` 面板按钮、面板右上角显示版本角标 → 安装成功

> 判断是否加载成功的唯一标准：**面板右上角的版本角标**。
> 角标没变 = 浏览器缓存 / 没放对目录 → 再硬刷新一次。

### 方式 B：烤进镜像（Docker / 部署）

把 `st-rbq` 放进镜像里的 `data/default-user/extensions/` 即可，无需构建。

## 配套预设与世界书

本仓库 `presets/` 里已经带了可直接导入的两份文件：

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| **`presets/斯拉RBQ-零.json`** | **主预设**（36 条提示词，含思考链 / 叙事 / NSFW 规则等） | 酒馆 →「AI 回复配置（预设）」→ **导入** → 选这个文件 |
| **`presets/RBQ世界书.json`** | **世界书**（100 条条目） | 酒馆 →「世界书」→ **导入** → 选这个文件，然后**启用**（设为全局或绑定角色卡） |
| `presets/index.json` | 扩展的「内置预设清单」 | **不用动**。以后换预设 = 往这个目录丢文件 + 改这里（扩展的「一键导入预设」会读它） |

### 在哪导入

```
预设：  顶栏「AI 回复配置」→ 预设下拉框旁的「导入」→ 选 JSON
世界书：顶栏「世界书」→「导入」→ 选 JSON → 勾选启用（或在角色卡里选中它）
```

> ⚠️ 导入预设会**覆盖当前预设**，建议先导出备份自己的。
> ⚠️ 世界书导入后必须**启用**才生效。

### 想换预设 / 加预设？

改 `presets/index.json` 即可，结构：

```json
{
  "items": [
    { "key": "zero",      "label": "斯拉RBQ · 游戏：零", "file": "斯拉RBQ-零.json", "kind": "preset",    "version": "1.0.0" },
    { "key": "worldbook", "label": "RBQ 世界书",         "file": "RBQ世界书.json",  "kind": "worldinfo", "version": "1.0.0" }
  ]
}
```

- `kind`：`preset`（预设）/ `worldinfo`（世界书）
- 加一行 → 扩展「设置 → 一键导入预设」里就多一个按钮，**不用改代码**

## 侧路 API 怎么配

> 位置：**面板 → 侧路 API 页**

| 字段 | 说明 | 默认 |
|---|---|---|
| 接口地址 | OpenAI 兼容地址，如 `https://api.deepseek.com/v1` | 空 = 用酒馆里当前连接的 API |
| API Key | 对应的 Key | 空 = 用酒馆的 |
| 模型 | 如 `deepseek-chat` | 空 = 用酒馆的 |
| 最大并发 | 同时跑几个侧路任务 | **3** |
| 超时 (ms) | 单次请求超时 | **120000**（120 秒） |
| 重试次数 | 失败自动重试几次（指数退避） | **3** |
| 预设注入标记 | 预设里名字含此符号的提示词 → 自动拼进侧路提示词 | `🔒` |

**任务开关**：填表 / 记忆 / 大总结 / 附加内容。想省 token 可以只开「填表」。

**留空 = 用酒馆自己的连接**：只有一个 API 的话全留空即可。

> 侧路页有「测试连接」和「预览提示词」两个按钮 —— 出问题先点它们。

## 回滚机制（重新生成 / 删除楼层）

这是本扩展最用力做的部分：

| 你的操作 | 结果 |
|---|---|
| **点「重新生成」** | 表格立刻回到**这一楼写入之前**的状态（快照还原，一字不差）；发给 AI 的也是回滚后的数据 |
| **删除最后一楼** | 回到**上一楼结束时**的状态 |
| **删除中间某楼** | **只撤销那一楼**写入的东西，后面的楼层数据**保留** |
| **删掉唯一那一楼** | 整库清空（剩下的聊天里已经没有剧情了）→ AI 只会收到「数据库为空」提示 |
| **滑动词（swipe）** | 同「重新生成」 |

细节：

- 每一楼都存两个快照：`beforeSnapshot`（写入前）/ `afterSnapshot`（写入后）
- 旧版本记的楼层缺快照 → 启动时**自动回填**（第 N 楼的 before = 第 N-1 楼的 after，数学上精确）
- 回滚后**立刻重推给 AI**，不会出现"AI 还在用被删楼层的数据"这种错位
- 回滚期间**冻结写入 15 秒**，防止上一轮的收尾定时器把数据写回来

## 角色设定自动包裹

打开酒馆时会**自动**做两件事（老 RBQ 的功能）：

1. 把 `{{user}}` 的角色设定用 `<{{user}}角色设定> … </{{user}}角色设定>` 包起来（幂等，不会重复包）
2. 把插入位置改成 **「聊天内 · 深度 0」**（比塞在提示词里更靠近正文，权重更实）

- 开关：**设置 → 用户角色设定（Persona）**
- 自动路径**不弹气泡**，只在控制台打日志（`F12` 搜 `角色设定`）
- 手动路径：「立即应用」按钮（有气泡反馈）→ 改完**不用刷新页面**，酒馆的设定框会自己更新
- 想还原：关掉开关，标签会被去掉

## 预设位置标记

在**预设**里，把提示词的**名字**改成带标记，扩展就会把它自动拼给侧路 AI：

| 名字写成 | 内容去哪 |
|---|---|
| `🔒↓ 表格口径` | 拼到侧路提示词**上面** |
| `🔒↑ 输出格式` | 拼到侧路提示词**下面** |
| `🔒 某某`（不带箭头） | 当"下面"处理 |
| 名字里没有 `🔒` | **不会被带上** |

最终形状：

```
[🔒↓ 第1条]
[🔒↓ 第2条]          ← 多个同类按预设里的顺序
（空行）
【侧路 API 提示词本体】
（空行）
[🔒↑ 第1条]
[🔒↑ 第2条]
```

**消息归属：一律按「系统」发** ✓ —— 预设里那条提示词原本设成用户 / AI 助手也好，
发侧路时都会被当成系统内容并进提示词（侧路提示词本体与正文也走系统）。
- 基础符号可改：**侧路 API 页 → 预设注入标记**（默认 `🔒`）
- 核对实际结果：`F12` 执行 `RBQ.sidePreviewPrompt('随便一段正文')`

## 正则工坊

向导七步（和 RBQ 老配置菜单一样）：

```
① 检索类型（标签 / 文本 / 符号 / 高级正则）
② 内容
③ 标签处理模式（整块 / 仅标签 / 保留标签清空内容）
④ 处理方式（删除 / 仅对用户隐藏 / 仅对 AI 隐藏 / 替换）
⑤ 作用范围（AI 输出 / 用户输入 / 斜杠命令）
⑥ 脚本名（自动加 RBQ- 前缀）
⑦ 预览 → 🚀 一键创建
```

- 装完**自动刷新**酒馆的正则列表（不用刷新页面）
- 卡片顶部显示「全局正则里现在共 N 条」
- 「📋 管理已建」可逐条删除 / 全部卸载；也能「导出 JSON」手动导入

## 常见问题

**Q：填表几乎是"秒"完成的，而且角色名固定是某个我没写过的名字？**
侧路接口填成了某个**本地假模型**地址。去「侧路 API」页把地址 / Key / 模型**清空**（留空 = 用酒馆自己的连接）。

**Q：表格里已经有数据了，但我没配侧路？**
本扩展**只在侧路写表**；正文里的 `data` 标签**不会被解析**。数据可能来自别处（别的插件 / 手动导入）。

**Q：想核对"此刻到底发给 AI 什么"？**
`F12` 执行 `RBQ.previewTableData()`（发给主 AI）或 `RBQ.sidePreviewPrompt('正文')`（发给侧路）。

**Q：数据库为空时 AI 会不会瞎编时间地点？**
不会。空表时会明确告诉它「数据库为空，按角色卡 / 世界书 / 预设自由发挥」，不塞任何假数据。

**Q：进度卡片一直显示「收尾中…」？**
后台还有任务在跑（收口 / 补写）。完成后会自动变「已完成」并在几秒后消失。想立刻停：卡片上的「终止」。

**Q：点了「终止」但侧路好像还在跑？**
正在飞的那一次请求断不掉（酒馆接口不支持中断），但**后续任务与所有写表都会停下**。

**Q：头像上传了，视图坞没变？**
早期版本有这个 bug（渲染时两边都画了首字）。更新到最新版即可。

**Q：角色设定没有自动被包起来？**
1. `F12` 搜 `角色设定`，看有没有日志（会自动重试 10 次 / 约 20 秒）
2. 若日志说失败 → 设置页点「立即应用」，并把「查状态」的结果发出来（不同酒馆版本字段位置不同）

**Q：版本角标没变？**
硬刷新（`Ctrl + Shift + R`）。**角标是判断新版本有没有加载的唯一标准。**

## 目录结构

```
st-rbq/
├─ manifest.json           扩展清单（入口 js / css 指向）
├─ boot-v2930.js           带版本号的入口（换版本时换名字，避开浏览器缓存）
├─ index.js                主入口：事件绑定 / 回滚 / 侧路调度 / 对外 API（window.RBQ）
├─ core/                   核心逻辑（35 个模块）
│  ├─ store.js             存储三层：extensionSettings / chatMetadata / 每条消息的锚点
│  ├─ txn.js               事务：把操作应用到表格（含逐格 undo 记录）
│  ├─ protocol.js          <data> 协议解析（标签 → 表 / 列）
│  ├─ schema.js            表结构
│  ├─ sideApi.js           侧路 API 客户端（重试 / 超时 / 并发）
│  ├─ sidePipeline.js      侧路任务编排（填表 / 记忆 / 大总结 / 附加）
│  ├─ prose.js             从 AI 输出里取出"正文"（丢掉思考块 / 小总结等）
│  ├─ memory.js            长期记忆：归档 + 召回
│  ├─ delta.js             按楼层算差量 → 只撤销某一楼
│  ├─ expand.js            技能 / 战斗 / 离场 / 记忆 的规则展开
│  ├─ persona.js           角色设定包裹 + 插入位置
│  ├─ regexWorkshop.js     正则工坊
│  └─ ...
├─ prompts/prompts.js      给 AI 的提示词与数据序列化
├─ data/                   默认表结构 / 别名 / 词表
├─ presets/                ⭐ 预设 + 世界书（要上传的就是这里）
```

## 开发与测试

- **零构建**：改完 JS 直接硬刷新酒馆即可。唯一的"构建"是发版时换入口文件：
  - 改 `manifest.json` 的 `js` → 新的 `boot-vNNNN.js`（内容只有一行 `import './index.js?v=NNNN';`）
  - 同步 `index.js` / `ui/panel.js` / `ui/views/dashboard.js` 的 `?v=NNNN` 与角标版本号
  - 目的：**避开浏览器缓存**（角标是判断版本的标准）
- **核心冒烟测试**（纯 Node，不需要酒馆）：

```bash
node tools/smoke-test.mjs
```

- **结构 / 别名生成**（改表结构或加别名时）：

```bash
node tools/build-schema.mjs  <表配置.json>  data/default-schema.json
node tools/build-aliases.mjs
```

- **调试用 API**（`F12` 直接调）：

发版流程（**必读**）：见 [`docs/发版流程.md`](docs/发版流程.md) —— 核心就一条：
**每次发版都要改 `manifest.json` 的 `version`**，插件内置的更新检查就是比这个值 ✓

```js
RBQ.sidePreviewPrompt('一段正文')  // 看侧路这次会发出去什么
RBQ.previewTableData()            // 看发给主 AI 的表格数据
RBQ.personaStatus()               // 角色设定状态
RBQ.personaApply()                // 手动跑一次包裹
RBQ.sideTest()                    // 测侧路连接
RBQ.getAll()                      // 当前所有表
RBQ.updateStatus()                // 更新检查状态（当前/远端/用的哪个源）
RBQ.updateCheck({force:true})     // 立刻查一次更新
RBQ.updateRepo()                  // 仓库地址
RBQ.getRev()                      // 当前版本号
```
